# 直播带货 AI Agent · 项目文档

> 本文档为项目唯一权威文档，覆盖背景、架构、进度、踩坑、数据口径全维度。

---

## 一、项目概述

基于 LangGraph + RAG 的直播带货话术辅助系统：实时接入弹幕 → LLM 意图识别 → ChromaDB 向量检索 → 生成推荐话术与执行策略 → WebSocket 实时推送到前端。帮助主播在海量弹幕中实时捕捉购买意向、价格疑虑、竞品对比等关键信息并精准回应。

前端 Vue 3 + TypeScript（Element Plus + ECharts + Pinia），后端 FastAPI + LangGraph StateGraph + ChromaDB + SQLite。

---

## 二、项目背景

直播带货已成为电商核心渠道，主播需同时关注商品介绍、观众互动、促销引导等多重任务。弹幕信息量大、节奏快，主播很难实时捕捉关键信息（购买意向、价格疑虑、竞品对比等）并精准回应。本系统用 AI Agent 实时分析弹幕语义，结合商品知识库 RAG 检索生成针对性话术推荐，把握每一个转化机会。

## 五、核心功能

| 模块 | 说明 |
|------|------|
| 实时弹幕采集 | WebSocket 接入直播弹幕流，支持多平台 |

| 节点级兜底 | 意图回落 other、置信度 0.3、话术占位文案，任一节点异常不中断 |

## 六、架构设计

**LangGraph 六节点工作流**：`预处理 → 意图识别 → RAG 检索 → 话术生成 → 策略推荐 → 结果整合`，TypedDict 约 19 字段状态流转。

**双通道通信**：
- HTTP：弹幕提交、分析结果查询、话术管理
- WebSocket：实时弹幕流 + 分析结果推送，前端 3s 自动重连，弹幕上限 100 条

**看板实时性**：分析结果落库后，后端在同一帧广播里附带 `stats` 统计快照（`compute_stats()` 与 HTTP `/analysis/stats` 共用同一份实现，保证推送值与接口返回值同口径）；看板据此实时更新，另有 30s 低频兜底轮询，防推送断开时看板冻结。按主播筛选时后端不推（推送的是全会话快照），该场景走 HTTP 拉取。

**检索策略**：按意图 doc_type 过滤路由 → 命中不足回落全库 → top_k=5

**检索可解释性**：`rag_sources` 完整回传命中文档的 `title / score / type`（`type` 即 doc_type，标明命中商品知识库还是话术库），前端「检索来源」面板逐条展开。相关度 = `1 − 向量距离`，越高越接近。

## 八、踩坑记录

1. **LLM 输出 JSON 不稳定**：格式漂移即抛异常中断链路 → 首尾花括号容错解析 + 失败回退纯文本 + 每节点独立兜底。
2. **意图与检索范围错配**：价格弹幕命中产品参数文档，话术像念产品手册 → doc_type 过滤路由 + 命中不足回落全库。
3. **延迟远超目标**：设计 <2s，实测 20~50s/条（本机只有推理型模型，思考 token 数百）→ BATCH_SIZE=10、ANALYSIS_INTERVAL=5、单次广播、低置信度降级缓解；**简历不写实测延迟数字**。
4. **依赖版本锁死**：langchain==0.1.0 等旧版在 PyPI 无解 → 版本范围化，原清单留 `requirements.doc-pinned.txt`。
5. **新版 API 迁移**：langchain.schema → langchain_core.messages；LangGraph 新版禁止节点名与状态字段同名（strategy → strategy_plan）。
6. **MAX_TOKENS=500 空 content**：推理模型思考预算被截断 → 必须给足。
7. **看板恒为 0**：WS 链路只存弹幕不存分析结果 → 双链路补 AnalysisResult 持久化。
8. **中文向量精度差**：chroma 默认英文 MiniLM → EMBEDDING_PROVIDER 三选项（api/local_bge/chroma_default）。
9. **文档口径与代码脱节**：README 与本文件曾长期写着「WebSocket 广播未按 session_id 过滤、多会话会串」，实际连接管理器早已按会话分组（`ConnectionManager.broadcast(msg, session_id)` → `self.sessions.get(session_id, [])`），真正的限制在采集单例。**教训：限制类描述必须对着代码复核 —— 把自己的已实现能力写成缺陷，面试被追问时等于自黑**（2026-09-23 已修正）。

## 十、已知限制与待办

**已知限制**：
- **延迟**：本机推理型模型单条约 20~50s，不满足 <2s 设计目标；换非推理模型（deepseek-chat、qwen-turbo）可改善
- **向量模型**：`chroma_default` 为英文 MiniLM，中文检索精度一般；需装 sentence-transformers 用 bge-small-zh
- **多直播间并发**：WebSocket 广播**已**按 `session_id` 分组隔离（连接管理器按会话维护连接列表，不存在多会话串消息）；真正的限制在采集侧 —— `DouyinClient` 的弹幕采集是全局单例（单个 Playwright page、单个采集 task，`/live/capture/stop` 不区分主播），同一时间只能采一个直播间

**待办**：
- [x] WebSocket 按 session_id 分组广播（已完成）
- [ ] 采集侧支持多直播间并行（当前为全局单例）
- [ ] 接入非推理模型降低延迟
- [ ] 本地 bge 中文 Embedding
